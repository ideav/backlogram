# Стенд «книги и авторы» (ideav/backlogram#918)

Повтор замера [habr 414255](https://habr.com/ru/articles/414255/) (2018): обычная схема MySQL против единой таблицы ядра Интеграм на 1 048 552 книгах и 142 654 авторах. Материал — статья блога `blog-v2/src/content/posts/knigi-i-avtory-zamery-vosem-let-spustya.md`.

## Запуск

Нужны docker (compose v2), node ≥ 18, python 3 и клон [ideav/crm](https://github.com/ideav/crm): ядро собирается из него.

```bash
CRM_DIR=/path/to/crm ./run.sh 7     # 7 раундов на каждый запрос, ~1,5 ч
```

Порты: MySQL — 127.0.0.1:13918 (root / root918), ядро — 127.0.0.1:18918, база `bk`, токен стенда `bk918tok`.

## Что внутри

| Файл | Что делает |
|---|---|
| `compose.yaml` | MySQL 8.0 (2 CPU, 2 ГБ, buffer pool 128 МБ) + ядро из `$CRM_DIR` |
| `mkbase.sql`, `ru_tpl.sql` | таблица `bk` в структуре ядра, служебные строки шаблона, пользователь стенда |
| `schema.mjs` | таблицы «Автор», «Книга» (ссылка на автора, Страниц, Год) через API ядра → `state.json` |
| `gen.py` | синтетические данные, seed 918; один и тот же набор пишется в обе схемы |
| `load.sql` | обычная схема с индексами статьи 2018 года + загрузка строк ядра |
| `idx-v1.sql` | индексы, которые поставил бы DBA: `(year, pages)`, `(author, pages)` |
| `reports.mjs` | запросы q1–q7 как отчёты ядра |
| `bench.php` | замерщик: обычная схема (SQL), ядро (HTTP `report/<id>?JSON_KV`) и SQL, который построило ядро (из `TRACE_IT`); медиана по раундам |
| `results-*.json` | сырые результаты: все прогоны и оба SQL по каждому запросу |
| `cover.mjs` | обложка статьи (1200×630, SVG + PNG в `blog-v2/public/uploads`); нужен `npm install` в `blog-v2` ради sharp |

## Результаты

- `results-v0-2018idx.json` — обычная схема с индексами 2018 года, 5 раундов.
- `results-v1b-fairidx.json` — обычная схема + `idx-v1.sql`, 7 раундов.
- `results-v2-core.json` — то же, ядро — crm `main` с ideav/crm#5472; цифры статьи.

Хост замера общий: отдельные раунды шумят до 2,5 раза, поэтому в статье — медианы 7 раундов, а сырые прогоны лежат рядом.
