# Доверенные площадки РСЯ: белый список, собранный чёрным

Вторая кампания к лендингу на отдельном домене — **традиционная**: платим за клики,
но показываемся только там, где хотим показываться. Первая кампания (оплата за
конверсии, [`excel-cpa-campaign.md`](excel-cpa-campaign.md)) устроена ровно наоборот
и площадки не чистит вовсе — там мусорный клик бесплатен.

## Главное ограничение: белого списка в Директе нет

У кампании есть только список **запрещённых площадок** — до **1000 доменов**
(`GENERAL_DOMAIN_BLACKLIST_SIZE` в ограничениях аккаунта, проверено по API).
Сказать «показывайся только на РБК, Авито и Хабре» нельзя. Поэтому белый список
ведётся наоборот:

1. В [`rsya-whitelist.json`](rsya-whitelist.json) лежит список доверенных доменов.
2. [`scripts/direct-rsya-whitelist-sync.mjs`](../../scripts/direct-rsya-whitelist-sync.mjs)
   берёт отчёт по площадкам, выбрасывает всё, чего нет в списке, и дописывает в запрет.
3. Запускается регулярно: каждая новая площадка успевает открутить показы до
   следующего прогона. Это неизбежная плата за отсутствие белого списка.

```bash
# посмотреть, что будет забанено (ничего не меняет)
DIRECT_TOKEN=… node scripts/direct-rsya-whitelist-sync.mjs --campaigns 712855945,712874633

# записать запрет в кампании
DIRECT_TOKEN=… node scripts/direct-rsya-whitelist-sync.mjs --campaigns 712855945 --apply

# сохранить накопленный список, чтобы новая кампания стартовала уже с ним
DIRECT_TOKEN=… node scripts/direct-rsya-whitelist-sync.mjs --campaigns 712855945 --write-list
```

Поддомены разрешаются автоматически: `habr.com` в списке разрешает и `m.habr.com`.

## Что показал отчёт по действующим кампаниям

Выгрузка по РСЯ-кампаниям (`712855945`, `712874633`) за июль–сентябрь 2026:

- **990 площадок**, 1 065 кликов, 1 270 ₽.
- Из них **796 похожи на мобильные приложения** (`com.fungames.blockcraft`,
  `com.robtopx.geometryjumplite`, `com.block.juggle`) — 465 кликов и 531 ₽.
- Верх списка по кликам — не сайты, а биржи: `dsp.yandex.ru` (247), `game.yandex.ru`
  (122), `dsp-opera-exchange.yandex.ru` (68), `dsp-ironsource.yandex.ru` (40).
- Из доверенных площадок в отчёте есть ровно одна — `dzen.ru`, 14 кликов.
  **РБК, Хабра, Авито, Ведомостей, Коммерсанта — ноль показов.**

Отсюда вывод, который важнее самого бана: **одним чёрным списком на премиальные
площадки не попасть.** Их там нет не потому, что мешает мусор, а потому, что по
ставке 1–1,4 ₽ за клик такой инвентарь не покупается. Поэтому в традиционной
кампании ставка поднята до **25 ₽** — иначе запрет 990 площадок просто оставит
кампанию без показов вообще.

## Лимит в 1000 упирается сразу — и это меняет план

Сухой прогон синхронизатора по действующим РСЯ-кампаниям (без записи):

```
Площадок в отчёте: 990
уже запрещено: 0, добавляется: 987, итого: 987
```

То есть если перенести накопленный мусор в новую кампанию, **из 1000 мест сразу
занято 987**, и на всё будущее остаётся тринадцать. Значит переносить его нельзя:

- **новая кампания стартует с пустым запретом**, а не с выгрузкой из мусорных;
- на ставке 25 ₽ инвентарь другой и хвост несопоставимо короче — банить придётся
  то, что реально показалось на дорогой ставке, а не то, что налипло на ставке 1 ₽;
- если хвост всё равно растёт быстрее, чем его чистишь, значит инструмент не тот:
  это сигнал идти в прямые размещения, а не искать обходные пути в РСЯ.

`--write-list` в синхронизаторе существует ровно для одного случая: снять список
руками, посмотреть глазами и решить, что из него переносить. Автоматического
переноса нет намеренно.

## Кампания

[`scripts/direct-create-trusted-rsya-campaign.mjs`](../../scripts/direct-create-trusted-rsya-campaign.mjs)
создаёт её остановленной. Отличия от кампании с оплатой за конверсии:

| | оплата за конверсии | доверенные площадки |
| --- | --- | --- |
| За что платим | за цель (500 ₽) | за клик (~25 ₽) |
| Площадки | любые, не чистим | только из белого списка |
| Мусорные ключи | да, это опора схемы | **нет**: за клик по ним платим деньгами |
| Ключи | горячие + смежные + мусор | горячие + смежные |
| Поиск | отдельной кампанией | выключен |

## Регламент пополнения

- **Белый список пополняет владелец.** Текущий набор в `rsya-whitelist.json` —
  стартовый: названы РБК, Авито и Хабр, остальное добавлено по однотипности и
  ждёт правки.
- **Чёрный список пополняет скрипт.** Раз в неделю (а первые две недели — раз в
  два-три дня, пока идёт основной приток новых площадок).
- **Когда упрёмся в 1000** — скрипт скажет об этом прямо и покажет, что не влезло.
  Дальше вариантов два: заводить вторую кампанию под тот же белый список или
  признать, что инструмент исчерпан, и покупать премиальный инвентарь не через РСЯ.
  Приоритет при переполнении — по расходу: баним сначала то, что дороже стоило.

## Чего эта схема не даёт

- **Гарантии, что показы будут именно на РБК и Хабре.** Запрет чужого не создаёт
  спроса на своё: если ставка не дотягивает до аукциона на этих площадках, показов
  не будет ни на них, ни где-либо ещё.
- **Мгновенной чистоты.** Новая площадка успевает открутить показы до ближайшего
  прогона синхронизатора.
- **Дешёвого трафика.** Это и не цель: смысл кампании — проверить, конвертирует ли
  качественный дорогой трафик лучше, чем 2 136 кликов по 3,20 ₽, давшие три конверсии.
