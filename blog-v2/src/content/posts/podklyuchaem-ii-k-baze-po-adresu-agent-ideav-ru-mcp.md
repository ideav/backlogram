У каждой базы на ideav.ru есть адрес, по которому к ней подключается ИИ-ассистент: `https://agent.ideav.ru/mcp/<база>`. Устанавливать ничего не нужно, ни Node.js, ни npm-пакеты: адрес добавляется в Claude, ChatGPT или другой клиент с поддержкой MCP как коннектор. Доступ даёт MCP-токен, который вы выпускаете в самой базе, с нужными правами и сроком.

Если вам нужен локальный вариант, который запускается на вашем компьютере, смотрите инструкцию [«Подключаем Claude к базе данных через MCP»](/posts/podklyuchaem-claude-k-baze-dannyh-cherez-mcp/) — там сервер `integram-mcp` через `npx`. Здесь — удалённый сервер, который работает за вас.

## Шаг 1. Заведите пользователя для ИИ

Агент работает с правами пользователя, чей токен ему дали, и видит только то, что разрешено роли этого пользователя. Поэтому лучше завести ИИ отдельного пользователя с узкой ролью, а не отдавать ему свой доступ. Например, для ассистента, который отвечает клиентам о статусе заказа, хватит роли «только чтение таблицы заказов».

Отдельный пользователь даёт и чистый журнал: все правки агента видны в журнале базы под логином с суффиксом `~ai`, например `assistant~ai`.

## Шаг 2. Выпустите MCP-токен

Войдите в базу под этим пользователем и откройте страницу `https://ideav.ru/<база>/_mcp_token`. На ней:

- **права:** чтение есть всегда, остальные отмечаются галками — запись, удаление, права (пользователи и роли), схема (новые таблицы и колонки);
- **срок:** от 1 до 90 дней, по умолчанию 30;
- кнопка **«Выпустить»** — токен показывается один раз, скопируйте его сразу;
- **список токенов** со сроками и правами и кнопка **«Отозвать»** у каждого.

Права токена никогда не шире прав пользователя: если роли запрещено видеть таблицу, токен её тоже не откроет. Токен годится только для MCP — войти им в интерфейс базы или ходить в её API нельзя.

## Шаг 3. Подключите клиента

У адреса два вида:

```
https://agent.ideav.ru/mcp/<база>            токен в заголовке Authorization: Bearer <токен>
https://agent.ideav.ru/mcp/<база>/<токен>    для клиентов, где нельзя задать заголовок
```

Вместо `<база>` подставьте имя своей базы — то, что стоит в адресе после `ideav.ru/`.

**Claude Code** — одной командой:

```sh
claude mcp add --transport http ideav-mydb https://agent.ideav.ru/mcp/mydb \
  --header "Authorization: Bearer <MCP-токен>"
```

**Claude Desktop и claude.ai** — «Настройки» → «Коннекторы» → «Добавить свой коннектор». В поле URL вставьте `https://agent.ideav.ru/mcp/mydb/<токен>`, поля OAuth оставьте пустыми.

**ChatGPT** — «Настройки» → «Приложения и коннекторы» → «Расширенные» → включите режим разработчика → «Создать». URL — `https://agent.ideav.ru/mcp/mydb/<токен>`, аутентификация — «Нет».

**Другой клиент** — сервер работает по протоколу streamable HTTP: запросы JSON-RPC отправляются методом POST на адрес выше.

## Шаг 4. Проверьте

Попросите ассистента: «Покажи список таблиц в базе». Он вызовет инструмент `list_tables` и перечислит таблицы, доступные вашей роли. Если таблиц меньше, чем вы ожидали, — дело в правах пользователя, а не в подключении.

## Что умеет агент

| Действие | Инструменты | Нужное право токена |
|---|---|---|
| Смотреть таблицы и их колонки | `list_tables`, `get_table_schema` | чтение |
| Искать и считать записи, открывать карточку | `list_objects`, `count_objects`, `get_object` | чтение |
| Запускать отчёты | `run_report` | чтение |
| Создавать и править записи | `create_object`, `update_object` | запись |
| Удалять записи | `delete_object` | удаление |
| Добавлять и переименовывать таблицы и колонки | `create_table`, `create_column`, `rename_table`, `rename_column` | схема |

Удалить колонку или таблицу через MCP нельзя ни при каких правах: правка схемы только добавляет и переименовывает, данные не теряются. Клиент видит, какие инструменты меняют данные, и по своим правилам спрашивает подтверждение перед записью и удалением.

## Как сузить права одного подключения

Токен с правом записи можно подключить к ассистенту в режиме только для чтения, не выпуская новый токен. Для этого добавьте к адресу параметр `allow`:

- `?allow=readonly` — только чтение;
- `?allow=delete` — из опасных прав остаётся только удаление, если оно есть в токене.

Параметр может только сузить права токена, расширить их нельзя. Без `allow` действуют все права токена.

## Безопасность

- **Адрес с токеном — это пароль.** Не публикуйте его и не пересылайте в открытых чатах. Сервер не пишет токены в журнал.
- **Утёк — отзовите.** На странице `/<база>/_mcp_token` нажмите «Отозвать» у нужного токена. Ваш вход в интерфейс и другие токены это не затронет.
- **Короткий срок лучше длинного.** Для пробы хватит нескольких дней, для постоянного ассистента — выпускайте новый токен по истечении срока.
- **Все правки видны.** Журнал базы показывает каждую правку агента под логином с суффиксом `~ai`, отдельно от правок людей и ИИ-чата.

## Если не работает

- **«нет токена пользователя базы»** — токен не дошёл до сервера: проверьте, что он стоит в заголовке `Authorization: Bearer …` или в конце адреса.
- **«MCP token expired or revoked»** — токен истёк, отозван или выпущен в другой базе. Выпустите новый на странице `_mcp_token` нужной базы.
- **«У вас нет прав на редактирование типов»** — у токена есть право «схема», но у роли пользователя нет права менять структуру базы. Права роли настраивает администратор базы.
- **Клиент пытается открыть поток (GET) и получает 405** — сервер принимает только POST. Выберите в клиенте транспорт streamable HTTP или используйте мост `mcp-remote`.

## Частые вопросы

### Чем удалённый MCP отличается от integram-mcp?

`integram-mcp` — npm-пакет, который запускается на вашем компьютере через `npx` и требует Node.js. Удалённый сервер `agent.ideav.ru/mcp` работает у нас: клиенту нужен только адрес и MCP-токен. Для баз на ideav.ru удалённый вариант проще, а права в обоих случаях проверяет сама база.

### Можно ли подключить ChatGPT, а не только Claude?

Да. Сервер работает по открытому протоколу MCP, поэтому подходит любой клиент с поддержкой удалённых MCP-серверов: Claude, ChatGPT в режиме разработчика и другие.

### Увидит ли агент данные, закрытые от пользователя?

Нет. Каждый запрос агента проверяет сама база с правами пользователя, которому выпущен токен. Права токена не бывают шире прав роли.
