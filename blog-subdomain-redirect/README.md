# blog.ideav.ru → ideav.ru/blog/ (301)

Блог переехал с поддомена в подпапку основного домена — issue [#522](https://github.com/ideav/backlogram/issues/522).
Здесь лежит `.htaccess`, который надо положить **в веб-корень поддомена
`blog.ideav.ru`** вместо старой копии блога.

## Зачем

Поддомен и подпапка отдавали один и тот же контент — это дубликат в выдаче.
После выкладки блог живёт в одном месте (`https://ideav.ru/blog/`), а поддомен
только передаёт на него накопленный вес.

## Порядок выкладки

1. Выложить свежую сборку блога в `<веб-корень ideav.ru>/blog/`
   (`cd blog-v2 && npm run build`, содержимое `dist/` — включая `.htaccess`).
2. Проверить, что блог на новом месте открывается: главная, статья, категория,
   поиск, `/blog/rss.xml`, `/blog/sitemap-index.xml`.
3. Только после этого заменить содержимое веб-корня `blog.ideav.ru` на этот
   `.htaccess`. Старые файлы блога можно удалить — правило не смотрит на диск.

Порядок именно такой: если сначала включить редирект, а сборку выложить потом,
поисковики поймают 301 в 404.

## Проверка

```bash
curl -sI https://blog.ideav.ru/                                   # 301 -> https://ideav.ru/blog/
curl -sI https://blog.ideav.ru/posts/integram-on-premise-lokalno/ # 301 -> .../blog/posts/integram-on-premise-lokalno/
curl -sI https://blog.ideav.ru/rss.xml                            # 301 -> https://ideav.ru/blog/rss.xml
curl -sI https://blog.ideav.ru/2026/05/integram-on-premise-lokalno # 301 -> /blog/2026/05/... -> /blog/posts/.../ (второй хоп)
```

Локально то же самое проверяется докером — см. `docs/verify-blog-move.md`.

## Что ещё сделать руками

- **Яндекс.Вебмастер**: «Переезд сайта» — указать `ideav.ru` как главное
  зеркало для `blog.ideav.ru`; добавить `https://ideav.ru/sitemap-index.xml`.
- **Google Search Console**: инструмент «Изменение адреса» для ресурса
  `blog.ideav.ru`; оба ресурса должны быть подтверждены.
- Не снимать редирект минимум год: 301 продолжает передавать вес, пока по
  старым адресам ещё ходят.
