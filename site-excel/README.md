# site-excel — лендинг «Excel → приложение» на отдельном домене

Отдельная сборка под рекламную кампанию с **оплатой за конверсии**. С сайтом в корне репозитория не связана: свой вход, свои компоненты, свой `dist-excel/`, свой счётчик Метрики. Устроена по образцу [`site-en/`](../site-en/README.md).

## Зачем отдельный домен

1. **Своя статистика.** Счётчик основного сайта (108758829) за всю историю рекламы принял **3 конверсии на 16 048 ₽** расхода. Стратегия «оплата за конверсии» учится на статистике цели, и эта история ей мешает.
2. **Изоляция риска.** Схема стоит на цели, спрятанной за первым кликом (см. ниже). Яндекс такие вещи со временем прикрывает — прикроют отдельный домен, а не `ideav.ru`.
3. **Бонус на пополнение.** Кампания под новый домен заводится отдельно, без наследства старых кампаний аккаунта.

## Как устроена конверсия

До первого клика на странице **нет целевой кнопки**. Её открывает кнопка «Сделать приложение из моего Excel» в первом экране: она раскрывает воронку — форму демонстрации и блок разбора с кнопкой **«Записаться на разбор»**. Клик по ней и есть цель, за которую Директ платит.

Цены, кейсы «было → стало», объяснение механизма и сравнение с Power Apps / Quickbase видны сразу (`Pricing.tsx`, `Cases.tsx`, `HowItWorks.tsx`, issue #613). Цены — по макету владельца; на ideav.ru те же услуги лежат в `src/data/services.mjs`, при смене сверять оба сайта.

```
загрузка страницы  →  [Сделать приложение]  →  воронка       →  [Записаться]  →  форма
                        price_open                           signup_click     lead
                                                          ↑ целевая цель кампании
```

Почему так: автомат, который открывает страницу и жмёт всё, что видит, до второй кнопки не доходит — в разметке её ещё нет. Поверх этого в [`src/conversion.ts`](src/conversion.ts) стоит мягкая проверка на человека (настоящий `isTrusted`-жест + больше 2,5 с на странице). Не прошла проверку — вместо `signup_click` уходит `signup_blocked`: конверсия не засчитывается и не оплачивается, но в отчётах видно, сколько таких заходов.

Проверка намеренно мягкая: стратегии нужно порядка **десяти конверсий в неделю**, иначе Директ душит показы и кампания встаёт. Перестраховка здесь стоит дороже пропущенного бота.

### Модальная заявка из карточек цен (#619)

Кнопки карточек блока «Сколько стоит» открывают модальное окно **«Заявка на экспресс-разработку приложений»** — по образцу формы ideav.ru/#cta; название карточки уходит в заявку (`plan`). Открытие окна целей не шлёт. Цель `express_lead` уходит только после того, как `order.php` ответил «принято» (обязательные поля, согласие, honeypot, лимит с IP), и тоже через проверку на человека — иначе `express_blocked`. Кликер, который жмёт всё подряд, дальше пустой формы не продвинется.

## Цели Метрики

Все — тип «JavaScript-событие», идентификаторы буква-в-букву:

| Цель | Когда | Зачем |
| --- | --- | --- |
| `price_open` | первый клик, раскрыт блок с ценой (с проверкой на человека) | наблюдение за воронкой |
| `signup_click` | клик «Записаться на разбор» | **целевая цель кампании** |
| `signup_blocked` | тот же клик, не прошёл проверку | измерять долю автоматов |
| `lead` | форма отправлена | учёт заявок |
| `express_lead` | модальная заявка из карточек цен принята (#619) | заявка, недоступная кликеру |
| `express_blocked` | та же заявка, не прошла проверку | измерять долю автоматов |

Почтовый адрес на странице — текстом, без почтовой ссылки: клик по ней — автоцель Метрики «Клик по email», достижимая с первого экрана.

## Страницы домена (issue #626)

Домен перестал быть одной страницей. Адреса:

| Адрес | Что это |
| --- | --- |
| `/` | лендинг, живое React-приложение |
| `/keysy/<slug>/` | четыре кейса «было → стало», по странице на каждый |
| `/sravnenie-power-apps/` | сравнение с Power Apps, Quickbase и конструкторами |
| `/<slug>/` | посадочные под рекламу и поиск (issue #657), по JSON-файлу на страницу в `landings/` |
| `/llms.txt`, `/pricing.md` | карта домена и прайс для языковых моделей |

Содержание всех страниц — в [`src/content.ts`](src/content.ts): кейсы, цены,
тексты сравнения и вопросы. Это единственный источник, из которого берут текст
сразу четверо — компоненты страницы, статические страницы, `vite.config.ts`
(`sitemap.xml`, `/llms.txt`, `/pricing.md`) и JSON-LD в
[`src/seo.ts`](src/seo.ts). Поэтому файл обязан оставаться чистыми данными:
ни JSX, ни импортов `react` — иначе его не подключит конфиг Vite.

**Пререндер.** [`scripts/prerender-site-excel.mjs`](../scripts/prerender-site-excel.mjs)
рисует `<Landing />` через `react-dom/server` и кладёт готовую разметку
в `#root` собранного `index.html`; он же собирает статические страницы.
До этого в сыром HTML не было ни H1, ни текста, ни цен — ИИ-боты
(GPTBot, ClaudeBot, PerplexityBot) JS не исполняют, и для них домен был пуст.
Снимок рисуется из тех же компонентов, что видит посетитель, поэтому
разойтись с живой страницей он не может.

На страницах-спутниках **нет скрипта приложения** — иначе React смонтировал бы
в `#root` лендинг и стёр бы содержимое. Значит, интерактивного на них нет
ничего, и целевой кнопки кампании в том числе: она живёт на главной за первым
кликом, и вынос её на спутник обошёл бы защиту от кликеров.

**Посадочные (issue #657).** Одна страница — один файл `landings/<slug>.json`,
шаблон — `src/pages/LandingPage.tsx`, проверки — `landings.mjs`. Пререндер
падает на длинных и повторяющихся title/description/H1, заглушках, запрещённых
формулировках, совпадающих блоках, отсутствии CTA и битых внутренних ссылках.
Кнопка посадочной ведёт на форму главной с `?from=<slug>` и UTM-метками; карта
волны, допущения и вопросы — [`docs/marketing/excel-landings-wave1.md`](../docs/marketing/excel-landings-wave1.md).

**Карточки Open Graph** — `public/og/*.png`, по одной на страницу; собираются
`npm run og-excel` (Satori → resvg, как карточки базы знаний) и коммитятся.

## Команды

```bash
npm run dev:excel                                          # localhost:5175
SITE_URL=https://<домен> METRIKA_ID=<счётчик> npm run build:excel
npm run og-excel                                           # перерисовать карточки OG
```

| Переменная | Что это | По умолчанию |
| --- | --- | --- |
| `SITE_URL` | схема и хост, без пути | **обязательна**, иначе сборка падает |
| `SITE_BASE` | путь на хосте | `/` |
| `METRIKA_ID` | счётчик Метрики | пусто — счётчик не подключается |

Сборка кладётся в `dist-excel/`. От хостинга нужно: статика, `https` и
работающий PHP для `order.php`. Редирект `www → bare` сборка берёт на себя —
в `dist-excel/.htaccess` (на Apache хостинга `AllowOverride` включён, проверено
на `ideav.ru`); если хостинг сменится на nginx, правило надо перенести в конфиг
руками.

Что проверять на собранном `dist-excel/`:

```bash
grep -c "<h1" dist-excel/index.html                # 1 — снимок на месте
grep -o "ПЕТФУД\|Атекс\|XCOM\|Спортзания" dist-excel/index.html | sort -u | wc -l   # 4
ls dist-excel/keysy/*/index.html dist-excel/sravnenie-power-apps/index.html        # 5 страниц
```

## Приём заявок

[`public/order.php`](public/order.php) — самостоятельный эндпоинт: проверка источника, honeypot, лимит 3 заявки с IP за 10 минут. Доставка **телеграмом первым**, почтой вторым: у доменов компании нет DMARC, письма ложатся в спам, и заявка, ушедшая только почтой, скорее всего не будет прочитана.

Настройки — через окружение или `public/order-config.php` (в git не входит): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ORDER_EMAIL_TO`.

Доставка устроена спулом ([`public/order-lib.php`](public/order-lib.php)): заявка сначала ложится на диск, потом делается попытка отправки, недоставленное добирает cron каждые 5 минут.

```
*/5 * * * * php /path/to/excel-to-app.ru/order-deliver.php
```

### Подтверждение адреса (issue #624)

Заявка на демонстрацию с **email**-контактом уходит оператору и сборщику не сразу: сначала на этот адрес идёт письмо со ссылкой (24 ч), и только переход по ней ставит заявку в работу. Причина — сборку делает ИИ-агент: заявка с опечаткой в адресе означает оплаченную сборку, о которой никто не узнает. Заявки на разбор, экспресс-разработку и заявки с телеграм-контактом идут как раньше.

Контур — тот же, что на ideav.ru, и код у него общий: `public/intake-*.php` здесь — **сгенерированные копии** из вебрута основного сайта, править их нельзя.

```bash
node ../scripts/sync-excel-intake.mjs     # из корня репозитория
node --test ../tests/excel-landing-confirm.test.mjs
```

Связка лендинга с библиотекой — [`public/order-intake.php`](public/order-intake.php), страница подтверждения — `public/order-confirm.php`, мост к сборщику — `public/order-build.php`. Настройки (`ORDER_QUEUE_DIR`, `ORDER_BUILD_TOKEN`, `ORDER_CONFIRM_*`), раскладку по серверу и то, почему `order.php` нельзя заливать целиком, см. [`docs/issue-624-double-optin-loop.md`](../docs/issue-624-double-optin-loop.md).
