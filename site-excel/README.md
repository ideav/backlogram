# site-excel — лендинг «Excel → приложение» на отдельном домене

Отдельная сборка под рекламную кампанию с **оплатой за конверсии**. С сайтом в корне репозитория не связана: свой вход, свои компоненты, свой `dist-excel/`, свой счётчик Метрики. Устроена по образцу [`site-en/`](../site-en/README.md).

## Зачем отдельный домен

1. **Своя статистика.** Счётчик основного сайта (108758829) за всю историю рекламы принял **3 конверсии на 16 048 ₽** расхода. Стратегия «оплата за конверсии» учится на статистике цели, и эта история ей мешает.
2. **Изоляция риска.** Схема стоит на цели, спрятанной за первым кликом (см. ниже). Яндекс такие вещи со временем прикрывает — прикроют отдельный домен, а не `ideav.ru`.
3. **Бонус на пополнение.** Кампания под новый домен заводится отдельно, без наследства старых кампаний аккаунта.

## Как устроена конверсия

До первого клика на странице **нет целевой кнопки**. Её открывает кнопка «Сделать приложение из моего Excel» в первом экране: она раскрывает воронку — форму демонстрации и блок разбора с кнопкой **«Записаться на разбор»**. Клик по ней и есть цель, за которую Директ платит.

Цены, кейсы «было → стало», объяснение механизма и сравнение с Power Apps / Quickbase видны сразу (`Pricing.tsx`, `Cases.tsx`, `HowItWorks.tsx`, issue #613). Цены — по макету владельца; на ideav.ru те же услуги лежат в `src/data/services.mjs`, при смене сверять оба сайта.

```
загрузка страницы  →  [Сделать приложение]  →  воронка       →  [Записаться]  →  форма
                        price_open                           signup_click     lead
                                                          ↑ целевая цель кампании
```

Почему так: автомат, который открывает страницу и жмёт всё, что видит, до второй кнопки не доходит — в разметке её ещё нет. Поверх этого в [`src/conversion.ts`](src/conversion.ts) стоит мягкая проверка на человека (настоящий `isTrusted`-жест + больше 2,5 с на странице). Не прошла проверку — вместо `signup_click` уходит `signup_blocked`: конверсия не засчитывается и не оплачивается, но в отчётах видно, сколько таких заходов.

Проверка намеренно мягкая: стратегии нужно порядка **десяти конверсий в неделю**, иначе Директ душит показы и кампания встаёт. Перестраховка здесь стоит дороже пропущенного бота.

### Модальная заявка из карточек цен (#619)

Кнопки карточек блока «Сколько стоит» открывают модальное окно **«Заявка на экспресс-разработку приложений»** — по образцу формы ideav.ru/#cta; название карточки уходит в заявку (`plan`). Открытие окна целей не шлёт. Цель `express_lead` уходит только после того, как `order.php` ответил «принято» (обязательные поля, согласие, honeypot, лимит с IP), и тоже через проверку на человека — иначе `express_blocked`. Кликер, который жмёт всё подряд, дальше пустой формы не продвинется.

## Цели Метрики

Все — тип «JavaScript-событие», идентификаторы буква-в-букву:

| Цель | Когда | Зачем |
| --- | --- | --- |
| `price_open` | первый клик, раскрыт блок с ценой (с проверкой на человека) | наблюдение за воронкой |
| `signup_click` | клик «Записаться на разбор» | **целевая цель кампании** |
| `signup_blocked` | тот же клик, не прошёл проверку | измерять долю автоматов |
| `lead` | форма отправлена | учёт заявок |
| `express_lead` | модальная заявка из карточек цен принята (#619) | заявка, недоступная кликеру |
| `express_blocked` | та же заявка, не прошла проверку | измерять долю автоматов |

Почтовый адрес на странице — текстом, без почтовой ссылки: клик по ней — автоцель Метрики «Клик по email», достижимая с первого экрана.

## Команды

```bash
npm run dev:excel                                          # localhost:5175
SITE_URL=https://<домен> METRIKA_ID=<счётчик> npm run build:excel
```

| Переменная | Что это | По умолчанию |
| --- | --- | --- |
| `SITE_URL` | схема и хост, без пути | **обязательна**, иначе сборка падает |
| `SITE_BASE` | путь на хосте | `/` |
| `METRIKA_ID` | счётчик Метрики | пусто — счётчик не подключается |

Сборка кладётся в `dist-excel/`. От хостинга нужно: статика, `https`, `www → bare` одним 301 и работающий PHP для `order.php`.

## Приём заявок

[`public/order.php`](public/order.php) — самостоятельный эндпоинт: проверка источника, honeypot, лимит 3 заявки с IP за 10 минут. Доставка **телеграмом первым**, почтой вторым: у доменов компании нет DMARC, письма ложатся в спам, и заявка, ушедшая только почтой, скорее всего не будет прочитана.

Настройки — через окружение или `public/order-config.php` (в git не входит): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `ORDER_EMAIL_TO`.
